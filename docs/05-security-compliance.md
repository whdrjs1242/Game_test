# 05. 보안 · 정책 준수

> 전제: 1단계는 **서버 없는 싱글플레이 게임**. 클라이언트 단독 보안은 완벽할 수 없으므로
> 목표를 명확히 한다 → **① 결제·유료 재화 보호 ② 일반 유저 수준의 변조 차단 ③ 리더보드 오염 최소화 ④ 개인정보·법규 완전 준수**.
> 치트는 대부분 본인 경험에만 영향(PvP 없음) — 과도한 차단으로 정상 유저를 해치지 않는다.

## 2. 세이브 보호

| 항목 | 방식 |
|---|---|
| 로컬 암호화 | **AES-256-GCM**, 키는 **Android Keystore** 에 생성(추출 불가, `setUserAuthenticationRequired(false)`) |
| 무결성 | GCM 인증 태그 + 추가 데이터(AAD)로 `schemaVersion`·`deviceLineageId` 바인딩 → 다른 기기/버전 파일 이식 차단 |
| 롤백 탐지 | `saveCounter` 를 DataStore 에도 별도 기록 → 세이브의 counter 가 더 작으면 "구버전 파일 복원" 탐지 → 최신 백업 사용 |
| 원자적 쓰기 | tmp 파일 → fsync → rename, 2세대 백업 유지 (전원 차단·크래시 시 손상 방지) |
| 클라우드 세이브 | Keystore 키는 기기 종속이므로, 클라우드 데이터는 **앱 내장 키(난독화 분할 보관) 기반 AES-GCM + HMAC** 로 보호. 목적: 일반 사용자 수준의 편집 방지(완전한 보호가 아님을 명시) |
| 변조 감지 시 | 즉시 차단하지 않고 → 직전 정상 백업으로 복구 시도 → 실패 시 클라우드 복구 제안. 반복 감지 기기는 리더보드 제출만 비활성 |

## 3. 메모리 변조 대응
- 재화·핵심 스탯은 `ObfuscatedLong` 래퍼로 보관: `stored = value xor key`, key 는 주기적으로 재생성, 체크섬 동시 보관.
  읽을 때 체크섬 불일치 → 변조 플래그.
- 유료 크리스탈은 **거래 원장(Ledger)** 로 관리: 잔액 = 획득 합 − 사용 합. 잔액 필드만 바꾼 경우 원장과 불일치로 탐지.
- 전투 결과 보상은 **서버 없이도 재검증 가능한 범위**에서 상한 검사: 스테이지별 최대 획득 골드·처치 수·클리어 시간 하한을 밸런스 데이터로 산출하여 초과 시 보상 상한 적용.

## 4. 결제 보안
| 항목 | 방식 |
|---|---|
| 서명 검증 | Play Console 의 라이선스 공개키로 `originalJson`·`signature` 검증 (RSA-SHA1/SHA256 — Play 규격 준수). 공개키는 분할·난독화 저장 |
| 중복 지급 방지 | `orderId`/`purchaseToken` 을 `PurchaseLedger` 에 기록, 이미 처리한 토큰은 무시 |
| 지급 누락 방지 | 앱 시작·재개 시 `queryPurchasesAsync` 로 미소비 구매 재처리, 지급 후 consume/acknowledge (3일 내 미승인 시 자동 환불되는 Play 규칙 대응) |
| 한계 명시 | 클라이언트 검증은 루팅+후킹으로 우회 가능 → 매출 규모 확대 시 **2단계: Firebase Functions 서버 검증 + Voided Purchases API 로 환불 악용 회수** |
| 결제 UI | Google Play 결제 시트만 사용(자체 결제 UI·외부 결제 유도 없음) |

## 5. 앱 무결성 · 코드 보호
- **R8 full mode** 난독화 + 리소스 축소, 디버그 로그 릴리스 빌드에서 제거.
- `android:debuggable=false`, `allowBackup` 은 세이브 제외 규칙 적용, `usesCleartextTraffic=false` + Network Security Config(HTTPS 전용).
- 설치 출처 확인(`PackageManager.getInstallSourceInfo`) 및 서명 인증서 해시 확인 → Play 외 설치·재서명 APK 감지 시 결제·리더보드 비활성 + 공식 스토어 안내.
- 루팅/에뮬레이터 탐지는 **차단하지 않고 플래그만** (정상 유저 오탐 방지) → 리더보드 제출 제한.
- 동적 코드 로딩(DexClassLoader), 리플렉션 기반 원격 코드 실행 금지 (Play 정책 위반 요소 배제).
- 2단계: **Play Integrity API** 로 기기·앱 무결성 판정 (서버 복호화 필요).

## 6. 리더보드 보호 (PGS)
- 제출 전 로컬 재검증: 무한의 탑 층수 ≤ (전투 시간 / 최소 층 클리어 시간), 스탯 대비 도달 가능 층 상한.
- 전투 시드 + 입력 로그 보관 → 이상치 기록은 로컬 재시뮬레이션으로 재검증 후 제출.
- Play Console 의 리더보드 **점수 범위(최소/최대) 설정**으로 비정상 점수 자동 배제, 필요 시 콘솔에서 플레이어 점수 숨김(변조 관리 기능) 사용.

## 7. 시간 조작 방지
- 오프라인 보상 계산은 `SystemClock.elapsedRealtime()`(부팅 이후 단조 시계) + 마지막 저장 벽시계 시각을 함께 기록.
- 벽시계가 뒤로 가면(역행) 보상 0 + 기준 시각 재설정, 앞으로 비정상 점프 시 상한(12시간) 적용.
- 네트워크 연결 시 HTTPS 응답의 `Date` 헤더(예: Google 서버)와 비교해 편차가 크면 일일 초기화를 보수적으로 처리.

## 9. 개발 보안 (저장소·빌드)
- 업로드 키스토어, `google-services.json`(민감도 낮지만 관리), Play 서비스 계정 JSON, 광고 단위 ID(운영) → **GitHub Secrets / 로컬 `local.properties`**, `.gitignore` 로 커밋 차단.
- 저장소에 비밀 유출 검사(시크릿 스캐닝 + pre-commit 검사), 의존성 취약점 알림(Dependabot) 활성화.
- 의존성은 Version Catalog 로 고정, Google/Maven Central 공식 저장소만 사용.
- Play App Signing 사용 → 업로드 키 분실·유출 시 교체 가능.

## 12. 히든 콘텐츠 보호 · 법적 고려

| 항목 | 방식 |
|---|---|
| 레시피 저장 | 히든 레시피·각성 조건은 평문 JSON 금지. `SHA-256(정렬된 재료 ID + 솔트)` 해시로만 저장하고, 합성 시 입력 조합을 같은 방식으로 해시해 비교 |
| 효과 코드 | 히든 효과 구현은 난독화된 효과 타입 ID로 분리, 문자열 리소스는 획득 후에만 복호화(앱 내장 키) |
| 진행도 | 각성 조건 진행 카운터는 세이브 원장에 포함(§2 무결성 적용) — 조작 탐지 시 히든 진행만 초기화 |
| 확률형 여부 | 히든 합성은 **100% 고정 결과**이므로 확률형 아이템 아님. 단 "히든 등급이 존재하며 조건 달성으로만 획득"을 확률 공시 페이지에 명시 |
| 공개 합성 | 오브·펫 등급 합성(무작위 결과)은 유료 재화로 얻은 아이템이 재료가 되므로 **확률 공시 대상** — 계열 60%/무작위 40%, 등급 내 균등을 공시 |
| 유일룬 | 룬 배너 0.03% 및 천장(1,000회) 공시, 이미 보유한 유일룬 제외 규칙도 공시 |
| AI 생성 에셋 | 생성 플랫폼 약관상 상업 이용 가능 플랜 여부 확인, 원본 프롬프트·생성일·플랜을 `LICENSES.md` 에 기록 |
